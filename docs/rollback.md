# 回滚手册

部署出问题（/api 报错、/status 长期 ok=false、错误率明显上升）时的恢复办法。两条路都能恢复到上一个正常版本，先用哪条看当时能不能进控制台、坏提交是否已定位。

## 路一：控制台重新部署上一版（最快）

Makers 控制台只保留最近 3 次成功部署的产物，可以直接把其中一个重新部署上去，不用动仓库。

1. 打开腾讯云 EdgeOne Makers 控制台，找到本项目。
2. 打开部署记录，找到最近一次正常的部署（看时间和提交信息确认）。
3. 对它点“重新部署”，等部署完成。
4. 核对：`https://hitokoto.xzccs.top/status?format=json&probe=read` 应为 ok=true、12/12；再请求一次 `/api`，确认能正常返回句子。

注意：这条路只换了线上跑的版本，仓库 main 里的坏提交还在。之后任何一次推 main 都会重新部署坏代码，所以恢复后仍要走路二把坏提交撤掉，否则下次部署又会坏。

## 路二：git revert 再推（彻底）

把坏提交从 main 里撤掉，推上去后 EdgeOne 会按源码重新部署。

1. 确认坏提交的 SHA（看最近几次提交，`git log --oneline -5`）。
2. 本地执行 `git revert <坏提交的 SHA>`，按提示完成 revert 提交。
3. 推到 main（与平时推送方式一致）。
4. 等部署完成（通常 3–4 分钟），按路一第 4 步核对 /status 与 /api。

如果坏提交之后还有别的提交，直接 revert 坏提交可能冲突；这时可改用 `git revert --no-commit <坏提交>` 后手动解决冲突再提交，或请熟悉仓库的人处理。

## 回滚不会动的东西

- KV：句子与统计的 KV 键按内容摘要分键，版本一变键就变。回滚代码不会清掉 KV，旧代码读旧键（若还在缓存期内），新代码读新键；不需要手动清理 KV。
- 句子库：`sentences/` 与 `sentence-index.json` 随代码一起回滚，内容摘要也会回到旧版本。
- 每日统计：`daily-stats.json` 存在 `stats-data` 分支，与 main 的回滚无关，不会丢失。

## 回滚后要做的事

1. 在仓库里确认坏提交已被 revert（路一恢复后别忘了这步）。
2. 看一眼 CI 是否通过、/status 是否 ok=true。
3. 把事故原因记下来：哪次提交、什么问题、以后怎么防。
